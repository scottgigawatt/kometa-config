# Support

Choose the right route so a small configuration question does not become a full-season mystery. Keep credentials, private server addresses, and unredacted logs out of public channels.

## Ask a question

Use the [🔥HADES🔥 Discord](https://discord.gg/BpEGzWwGYf) for informal setup and troubleshooting. Start with the [documentation index](index.md) and [testing guide](testing.md).

Support is best effort for a personal configuration, not a promise to support every Plex deployment.

## Report a reproducible bug

Open a [bug report](https://github.com/scottgigawatt/kometa-config/issues/new?template=bug-report.md). Include the repository commit, Kometa version, operating system, exact command, affected definition, expected result, and minimal reproduction.

Share only a short, manually reviewed diagnostic excerpt. Do not attach whole runtime logs, private configuration, environment files, or server URLs.

## Suggest an improvement

Use a [feature request](https://github.com/scottgigawatt/kometa-config/issues/new?template=feature-request.md) for behavior changes or a [documentation request](https://github.com/scottgigawatt/kometa-config/issues/new?template=documentation-enhancement.md) for unclear instructions.

For Kometa application behavior unrelated to these files, consult the [upstream documentation](https://kometa.wiki/en/latest/) and [upstream issue tracker](https://github.com/Kometa-Team/Kometa/issues).

## Report sensitive concerns

Follow the [security policy](SECURITY.md) for vulnerabilities and the [code of conduct](CODE_OF_CONDUCT.md#report-a-concern) for moderation concerns. Do not disclose sensitive details in public support channels.
